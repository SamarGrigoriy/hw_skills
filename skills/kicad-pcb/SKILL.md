# Печатная плата KiCad как код

Плата описывается Python-файлом проекта (`gen_pcb.py`) и собирается из нетлиста
схемы. Так она воспроизводима: одинаковое описание даёт побайтно одинаковый
`.kicad_pcb`, а `git diff` показывает «сдвинулся C204», а не перемешанный файл.
Файл платы — результат сборки: правка в интерфейсе KiCad перезаписывается,
закрепить дорожку значит внести её в описание.

Проверено на KiCad **10.0.4** (формат платы `20260206`), Python 3.13.

## Состояние инструментов

**Скрипты скилла не написаны.** Сейчас скилл — правила, порядок работы и
спецификация инструментов. Первая сессия разводки начинает с этапа 0:
пишет инструменты по `reference/tools.md` и проходит самопроверку. Ни одна
команда `scripts/…` не выдаётся за рабочую, пока скрипта нет. Этапы, для
которых нужен отсутствующий инструмент, не выполняются вручную «на глаз».

Работает уже сейчас — `kicad-cli`: заливка зон, DRC, сверка со схемой, картинки
слоёв, 3D-рендер и STEP (команды в `reference/format.md`). Python-модуль
`pcbnew` не использовать: `LoadBoard` падает с ошибкой сегментации.

| Файл | Что в нём |
|---|---|
| `reference/requirements.md` | опросник перед началом и карта требований |
| `reference/emc.md` | правила ЭМС-разводки с порогами линтера |
| `reference/placement.md` | порядок размещения, функция стоимости, уплотнение |
| `reference/assembly.md` | монтаж, сборка, обслуживание, посадка в корпус |
| `reference/router.md` | спецификация своего трассировщика |
| `reference/fab.md` | профили норм заводов, стек, правило числа слоёв |
| `reference/format.md` | формат `.kicad_pcb`, `.kicad_pro`, `.kicad_dru`, команды `kicad-cli`, ловушки |
| `reference/tools.md` | спецификация скриптов: `pcblib.py`, `place.py`, `route.py`, `emccheck.py`, `check.py`, `selftest.py` |

## Приоритеты

1. **ЭМС** — главное. Не уступается ради площади.
2. **Удобство монтажа и сборки** — зазоры, доступ паяльника и отвёртки,
   ориентация, ремонтопригодность.
3. **Интеграция в корпус** — контур, крепёж, высоты, порты напротив вводов.
   Если корпус задан, посадка в него — жёсткое условие.
4. **Компактность** — мягкая цель, не ограничение. Где ЭМС или монтажу нужно
   место, детали ставятся свободнее.

Конфликты: площадь уступает всегда; монтаж уступает ЭМС только с записью
причины в описании и согласованием человека.

## Этапы и ворота

Плата делается этапами, после каждого — ворота. Следующий этап не начинается,
пока ворота не пройдены. Слово «готово» пишется только с результатом ворот:
«DRC 0, сверка 0, ЭМС 0 ошибок, картинки просмотрены».

**Автоматических ворот мало.** Каждый PNG слоя, каждая вырезка зоны и каждый
3D-рендер **открываются и просматриваются**, а не принимаются по отчёту.
Дефект, увиденный глазами и не пойманный линтером, — повод дописать правило в
справочник и ловушку в `selftest.py`, а не только поправить плату.

| Этап | Что делается | Ворота |
|---|---|---|
| 0. Инструмент | написание и правка скриптов по `tools.md` | `selftest.py`: тестовые платы разведены, ловушки ЭМС, монтажа и корпуса пойманы целиком, собранные файлы открываются `kicad-cli` |
| 1. Требования | опрос человека по `requirements.md`, карта требований | **карта подтверждена человеком**: нет открытых и неподтверждённых строк |
| 2. Исходные данные | ворота схемы пройдены; нетлист; посадочные места; профиль завода; стек; **требования разводки из даташитов** со ссылками на страницы | все посадочные места существуют; сверка со схемой 0; требования даташитов записаны в описание |
| 3. Контур и неподвижное | контур по корпусу, крепёж, порты на кромках, антенны и запретные зоны, крупные детали | DRC 0 (кроме неразведённых); ENC 0 ошибок; PNG и 3D просмотрены |
| 4. Размещение | блоки по листам схемы, защита у портов, развязка у выводов, агрессоры вдали от жертв, зазоры монтажа | courtyard без пересечений; линтер стадии placement 0 ошибок; PNG слоёв и 3D просмотрены |
| 5. Критичные цепи | ВЧ 50 Ом, горячие петли преобразователей, кварцы, питание модема и радио — явной геометрией, закреплены | линтер стадии critical 0 ошибок; вырезка каждой критичной зоны просмотрена |
| 6. Трассировка | остальные цепи своим трассировщиком | разведено 100 %; DRC 0; сверка со схемой 0; линтер full 0 ошибок |
| 7. Земля и финал | заливка, сшивка, удаление островов | DRC 0; сверка 0; линтер full 0 ошибок; все PNG, вырезки и 3D просмотрены |
| 8. Уплотнение, по желанию | уменьшение контура без потерь по ЭМС и монтажу | таблица вариантов; вариант выбирает человек |

Правка инструмента (этап 0) меняет все платы, собранные им: после неё ворота
этапа 7 проходятся заново с просмотром всех картинок.

## Уточнение требований

Плата не начинается с размещения. До этапа 2 скилл **спрашивает человека** о
том, чего нет в документах проекта, и собирает карту требований. Полностью —
`reference/requirements.md`. Обязательный минимум:

- **Корпус**: модель или чертёж, внутренние размеры, крепление, высоты под
  крышкой, материал, вводы и окна.
- **Монтажные отверстия**: нужны ли, сколько, где, какой винт, металлизация и
  цепь, зона запрета под головку.
- **Порты подключения**, по каждому: USB, Ethernet, клеммники, антенные
  разъёмы, SIM, отладка, питание, кнопки и индикация — тип разъёма, кромка и
  положение вдоль неё, ориентация, выступ, доступ снаружи корпуса, подключение
  экрана, длина кабеля.
- **Габарит**: предельный размер, желаемый, форма, толщина.
- **Производство**: завод (профиль), партия, ручной или машинный монтаж.
- **Условия**: класс ЭМС, токи, напряжения, радио, греющиеся узлы.

Сначала читаются архитектура, схема и перечень элементов: человеку не задают
вопросов, ответ на которые есть в его документах, — такие строки идут в карту с
пометкой «из документации — подтвердить». Значение по умолчанию — только
предложение, которое человек видит и подтверждает.

## Остановки для человека

Скилл останавливается и спрашивает, а не решает сам, когда:

1. Карта требований не подтверждена или в ней открытые строки.
2. **Нужны 4 слоя.** Сам скилл слои не добавляет; вопрос — с тем, что не
   проходит, что испробовано, и таблицей сравнения (`fab.md`).
3. Монтаж или корпус должны уступить ЭМС.
4. Деталь нужно поставить на нижнюю сторону.
5. Плата не входит в заданный корпус или порт нельзя поставить напротив ввода.
6. Нужно исключение из правила с уровнем «ошибка».
7. Требования даташитов противоречат друг другу или правилам скилла.
8. Профиль завода не заполнен (сейчас — Резонит) или не выбран.
9. Нужной детали, посадочного места или 3D-модели нет. Детали подбираются по
   правилам скилла схем, из каталога Промэлектроники.

Вопрос должен позволять ответить одной строкой: что не проходит, ближайшие
варианты с последствиями, рекомендация.

## Правила коротко

Полностью — в справочниках; здесь то, что держать в голове всегда.

1. **B.Cu — сплошная земля.** Сигналы по F.Cu. Под быстрой дорожкой земля не
   прерывается (`emc.md`, раздел 1).
2. **Перемычки на B.Cu — короткие и редкие**, не под ВЧ, кварцем, модулем и
   дросселем; каждая — щель в единственной земле.
3. **Развязка — у вывода**, питание сначала на конденсатор, земля
   конденсатора — сразу переходным.
4. **Горячая петля преобразователя — наименьшая**, SW — минимум меди, обратная
   связь — в стороне.
5. **Кварц — вплотную к МК**, под ним и рядом — только земля.
6. **ВЧ-линия — 50 Ом по расчёту стека**, без переходных и прямых углов, с
   оградой переходных.
7. **Защита порта — первая от разъёма**, её земля — коротко; кабельные разъёмы
   на одной кромке.
8. **Быстрые цепи — не у кромки**, земля по периметру сшита.
9. **Никакой плавающей меди.**
10. **Ширина питания — по току**, падение на импульсе ≤ 50 мВ.
11. **Детали на одной стороне**, зазоры и доступ по способу монтажа.
12. **Посадка в корпус проверяется** контуром, высотами и 3D-рендером.

## Профиль завода и слои

| Профиль | Состояние | Рекомендовано: дорожка / зазор, переходное |
|---|---|---|
| JLCPCB | сверен 2026-09-15 | 0,15 / 0,15 мм, 0,3 / 0,6 мм |
| PCBWay | сверен 2026-09-15 | 0,15 / 0,15 мм, 0,3 / 0,6 мм |
| Резонит | **не заполнен** — плата под него не разводится | — |

По умолчанию **2 слоя**, толщина 1,6 мм. Переход на 4 слоя — только по
согласованию с человеком. В правила платы идут рекомендованные нормы, а не
предельные. Подробно — `reference/fab.md`.

## Связь со скиллом схем

Вход этапа 2 — выход этапа 5 скилла `kicad-schematic` «Перед разводкой»: у
каждого символа существующее посадочное место, повторная сборка схемы даёт
пустой `git diff`, ворота схемы пройдены. Если при разводке нужна правка
схемы (перестановка выводов, новая защита, другой корпус детали), она
делается в описании схемы и проходит ворота схемы, затем нетлист
пересобирается.

## Границы

- **Выпуск производства** — Gerber, сверловка, перечень и файл установки для
  монтажа, STEP для заказа, сборочный чертёж, панелизация — будущая функция
  скилла. Сейчас на плате только оставляется место под реперные знаки и
  технологические поля.
- **Ревью чужой платы** — будущая функция. Сторонний скилл `pcb-review` в
  репозитории написан под чужой проект и его пути; для плат этого проекта не
  используется.
- Схему этот скилл не правит — это `kicad-schematic`.
- Сертификацию ЭМС скилл не заменяет: он делает разводку, с которой изделие
  имеет шанс пройти испытания, и называет нормы, на которые опирается.
