# Схема KiCad как код

Схема описывается Python-файлом, собирается скриптом, проверяется автоматически.
Так она получается читаемой дважды: **на листе** — потому что символы ложатся на
сетку по построению, подписи не налезают на провода, блоки обведены и подписаны;
**в git** — потому что diff показывает «сменился номинал R7», а не двенадцать
мегабайт перемешанных идентификаторов.

Проверено на KiCad **10.0.4** (формат `20260306`), Python 3.13, без единой внешней
зависимости: ни `kiutils`, ни `sexpdata` в системе нет и не нужны.

- `scripts/schlib.py` — ядро: символы, провода, метки, питание, иерархия листов,
  автопостановка подписей деталей по карте занятости листа.
- `scripts/check.py` — **ворота этапа**: сборка → линтер → ERC → PNG листов и рамок.
- `scripts/schcheck.py` — линтер читаемости (то, чего нет в ERC): топология и
  геометрия надписей по SVG самого KiCad.
- `scripts/kfont.py` — модель штрихового шрифта KiCad: ширина текста, покрытие глифов.
- `scripts/mksym.py` — свои символы по таблице выводов, корпус по длине имён.
- `scripts/symfind.py` — поиск символов и посадочных мест в библиотеках.
- `scripts/partfind.py` — подбор деталей из каталога Промэлектроники (в наличии).
- `scripts/bomgen.py` — перечень элементов с ценами, парт-номерами и суммой.
- `scripts/sexp.py` — разбор S-выражений: читать чужие и правленные руками схемы.
- `scripts/selftest.py` — самопроверка: координаты выводов против KiCad и
  линтер-ловушка (лист с заведомыми дефектами, которые обязан найти линтер).
- `reference/format.md` — формат `.kicad_sch` и его ловушки.
- `reference/conventions.md` — правила читаемой схемы.
- `reference/components.md` — каталог компонентов: подбор, вопрос при отсутствии, перепарсинг.
- `template/` — рабочий пример из трёх листов.

## Этапы и ворота

Схема собирается этапами, и **после каждого этапа — ворота**. Следующий этап
не начинается, пока ворота не пройдены. Слово «готово» в README, в отчёте или
в ответе пользователю пишется только с результатом ворот: «линтер 0, ERC 0,
листы просмотрены».

```bash
python3 .../scripts/check.py проект.kicad_sch --gen gen_sch.py   # одна команда
```

`check.py` собирает схему, прогоняет линтер (топология + геометрия надписей
по SVG KiCad) и ERC, рисует PNG каждого листа и вырезку каждой рамки в
`build/`. Ненулевой код возврата — ворота не пройдены.

**Автоматических ворот мало.** После «ВОРОТА ПРОЙДЕНЫ автоматически» каждый PNG
листа и каждой рамки **открывается и просматривается** (Read по файлу), а не
принимается на веру по отчёту. Линтер ловит известные классы дефектов, глаз —
всё остальное: подпись, оторванную от своей детали, тесноту, поток сигнала
справа налево. Всё, что увидено глазами и не поймано линтером, — повод
**дописать проверку в `schcheck.py` и случай в ловушку `selftest.py`**, а не
только поправить лист. Так в линтер попали слипшиеся подписи и подпись по ту
сторону провода.

| Этап | Что делается | Ворота |
|---|---|---|
| 0. Инструмент | правка `schlib.py`, `schcheck.py`, `mksym.py`, `kfont.py` | `python3 scripts/selftest.py` — ловушка поймана целиком, выводы совпадают с KiCad; `template/` проходит `check.py` |
| 1. Символ | `mksym.py` / символ из библиотеки | символ на пробном листе: `check.py` без ошибок, имена выводов не налезают друг на друга |
| 2. Лист (блок) | один `sheet_*.py` | `check.py` по проекту; просмотр PNG этого листа и всех его рамок |
| 3. Проект | все листы, корневой лист | `check.py`; глобальные метки без одиночек; просмотр **всех** листов после последней правки генератора |
| 4. Закупка | поля MPN/Price/Supplier | детали из каталога (`partfind.py`); `bomgen.py` без позиций с пустой ценой |
| 5. Перед разводкой | посадочные места, нетлист | у каждого символа существующий footprint; повторная сборка даёт те же uuid (`git diff` пуст) |

Правка ядра (`schlib.py`, `mksym.py`) меняет **все** листы сразу, поэтому после
неё ворота этапа 3 проходятся заново, с просмотром каждого листа.

Если `kicad-cli` недоступен, линтер переходит на модель шрифта и предупреждает,
что геометрия приблизительна. Такие ворота не считаются пройденными.

## Как писать описание схемы

```python
import sys; sys.path.insert(0, "путь/к/scripts")
from schlib import Project

pr = Project("pole_smart_pcb", outdir=".", title="Узел мониторинга почвы", rev="A")

# Верхний уровень: только блоки и связи между ними, ни одной пассивной детали.
pw = pr.sheet("power.kicad_sch", "Питание", (30, 50), (50.8, 25.4),
              pins=[("VBAT", "input"), ("+3V3", "output")])

# Внутри листа: символ, провод от вывода к выводу, метка, пояснение.
u1 = pw.sym("U1", "Regulator_Linear:TPS7A0533PDBZ", (100, 60),
            value="TPS7A0533", footprint="Package_TO_SOT_SMD:SOT-23-3",
            fields={"MPN": "TPS7A0533PDBZR", "Manufacturer": "TI",
                    "Supplier": "LCSC", "Price": "50",
                    "Alt": "XC6206P332MR", "Note": "Iq < 1 мкА — критично"})
pw.wire(u1.pin("1"), (80, 60))
pw.label((80, 60), "VBAT")
pw.power("GND", (100, 80))
pw.note((20, 20), ["Ток покоя стабилизатора попадает прямо в сутки автономии:",
                   "1 мкА против 50 мкА — это разница между сезоном и месяцем."])

print(pr.check())      # сверка выводов листов с метками внутри
pr.save()
```

Координаты выводов **не подбираются на глаз**: `u1.pin("1")` возвращает точку
на листе с учётом поворота и зеркала. Подписи деталей тоже не расставляются
вручную: `save()` ставит ссылку и номинал туда, где они ни на что не ложатся
и не уходят из рамки своего блока; если места нет, сборка печатает
предупреждение «нужна раздвижка» — это сигнал раздвинуть детали, а не
ставить подпись руками. Провод, не дотянутый до вывода на сотую
долю миллиметра, выглядит соединённым и не соединён.

### Что даёт лист

| Метод | Назначение |
|---|---|
| `sym(ref, lib_id, at, value=, footprint=, angle=, mirror=, dnp=, fields=)` | символ; `fields` уходят в BOM |
| `wire(a, b)` / `bus([p1, p2, p3])` | провод / ломаная |
| `label(at, "ИМЯ")` | имя цепи в пределах листа |
| `glabel(at, "ИМЯ")` | глобальная цепь, видна на всех листах |
| `hlabel(at, "ИМЯ", shape=)` | вывод блока изнутри дочернего листа |
| `power("GND", at)` / `power("+3V3", at)` | символ питания; ссылку присвоит `save()` |
| `junction(at)` / `nc(at)` | точка соединения / «не подключено» |
| `note(at, ["строка", ...])` | пояснение |
| `box(a, b, "Заголовок")` | рамка функционального блока |

`Project.check()` сверяет выводы листов с иерархическими метками внутри них и
ищет повторяющиеся ссылки. Расхождение имени вывода и метки — самая частая
ошибка в иерархии: KiCad считает их разными цепями, и блок молча не подключается.

Выводы листа `pins=[("ZC", "input"), ("TRIAC1", "output")]` встают так: вход
слева, остальное справа. Третьим элементом сторона задаётся явно —
`("OW1", "bidirectional", "left")`: двунаправленная шина к блоку, стоящему
слева, иначе обходит свой блок кругом. Взаимное расположение блоков на верхнем
листе выбирается так, чтобы провода между ними шли без пересечений; лесенку
из нескольких проводов поворачивают правее для каждого следующего нижнего.

## Правила читаемой схемы

Полностью — в `reference/conventions.md`, коротко:

1. **Сетка 1,27 мм**, без исключений. `snap()` притягивает координаты сам.
2. **Поток слева направо**, питание сверху, земля снизу. Читатель не должен
   искать, откуда пришёл сигнал.
3. **Верхний лист — только блоки.** Ни резистора, ни конденсатора на нём.
4. **Один лист — один функциональный блок**, помещается на A4 без лупы.
5. **Провод длиннее 60 клеток заменяется меткой.** Провод через пол-листа
   читается хуже, чем имя цепи.
6. **Каждый блок обведён рамкой и подписан.** Всё — детали, их подписи,
   метки — целиком внутри одной рамки; рамки не пересекаются и не заходят
   в штамп.
7. **Каждый лист имеет пояснение** — что делает блок и почему так, а не иначе.
   Схема обязана объяснять себя; это то же правило, что для шапок файлов в коде.
8. **У каждой детали есть посадочное место и парт-номер из каталога.** Без
   первого не развести плату, без второго не купить деталь.
9. Подписи на схеме — по-русски, имена цепей — латиницей (`VBAT`, `SPI_SCK`).
10. **Надписи ни с чем не пересекаются**: ни с надписью, ни с проводом, ни
    с корпусом или выводом, ни с рамкой; между подписями разных деталей —
    зазор не меньше 0,5 мм. Подпись стоит со стороны своей детали, а не по
    ту сторону чужого провода. Подписи не бывают вверх ногами.
11. **Только глифы шрифта KiCad**: «₽», «№», «™», «℃» печатаются квадратом —
    писать «руб.», «N», «°C».

## Подбор компонентов

Детали берутся **из каталога Промэлектроники** — товары в наличии, которые можно
купить сейчас. Каталог лежит в `~/Proj/3.Resourses/components/promelec/`, поиск
по нему к сайту не обращается. Полностью — `reference/components.md`.

```bash
python3 scripts/partfind.py stats                          # свежесть каталога
python3 scripts/partfind.py cats "линейные"                # ключ раздела: 1/15/108
python3 scripts/partfind.py params 1/15/108                # по каким параметрам фильтровать
python3 scripts/partfind.py find "" --cat 1/15/108 -p "Корпус=SOT-23" --min-stock 300 --sort price
python3 scripts/partfind.py show TPS7A0533PDBZR            # карточка целиком
```

1. Требования к детали — **до** поиска: параметры с запасом, корпус, партия.
2. Склад в каталоге ≥ количество на плату × партия. Аналог — тоже из каталога.
3. В поля символа: `MPN` как в каталоге, `Manufacturer`, `Supplier: Promelec`,
   `Price` из каталога, `Alt`.
4. **Подходящего нет — остановиться и спросить пользователя.** Не подставлять
   деталь по памяти и не брать молча «почти подходящую». В вопросе: что искал
   (раздел, фильтры), ближайшие кандидаты и чем не подходят, варианты решения.
5. **Раздел не спарсен или данные старше 30 дней** (`cats` это показывает) —
   тоже сказать пользователю: допарсивает раздел или ищет деталь в других
   магазинах он сам. Парсер по своей инициативе не запускать.
6. **Парсить вежливо**: не весь каталог, не параллельно, паузы не уменьшать,
   `/search/` не трогать (запрещён robots.txt). 403 от DDoS-Guard — «слишком
   часто»: парсер сам ждёт, блокировку не обходить.

## Подбор символов и посадочных мест

```bash
python3 scripts/symfind.py sym  "TPS7A"        # найти символ
python3 scripts/symfind.py pins "Device:C"     # карта выводов
python3 scripts/symfind.py fp   "SOT-23"       # найти посадочное место
```

Имена символов не угадываются. Сначала спросить библиотеку, потом ставить:
несуществующий `lib_id` даёт схему с дырой на месте детали.

## Если KiCad не открывает файл

Он скажет «Не удалось загрузить схему» и **не укажет строку**. Порядок разбора —
в `reference/format.md`; первое, что надо проверить:

1. **Под-юниты внутри определения символа** (`C_0_1`, `R_1_1`) должны остаться
   **без** префикса библиотеки. Переименование их в `Device:C_0_1` ломает файл.
2. Баланс скобок с учётом того, что скобки внутри строк не считаются.
3. `version` соответствует установленному KiCad (`20260306` для 10.0.x).

Ошибка «схема содержит ошибки обозначения» при экспорте нетлиста — это
**повторяющиеся ссылки**, чаще всего `#PWR001` на двух листах сразу.
`Project.save()` перенумеровывает символы питания сквозным счётчиком именно
поэтому; при ручной правке следить за этим самому.

## Границы

Скилл делает схему. Печатную плату он **не разводит**: это скилл `kicad-pcb`,
его вход — выход этапа 5 «Перед разводкой». Сторонний `pcb-review` в
репозитории написан под чужой проект и для этой платы не используется.
