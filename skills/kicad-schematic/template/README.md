# Пример: питание датчикового узла

Три листа: корневой (блоки и разъём батареи), «Питание» (18650 → LDO → +3,3 В)
и «Нагрузка» (заглушка на месте микроконтроллера).

```bash
python3 gen_sch.py                              # собрать
python3 ../scripts/schcheck.py example*.kicad_sch   # читаемость
kicad-cli sch erc --severity-all --output erc.rpt example.kicad_sch
kicad-cli sch export pdf --output sch.pdf example.kicad_sch
python3 ../scripts/bomgen.py example.kicad_sch -o BOM.md --qty 30
```

Пример держится в состоянии **0 ошибок линтера, 0 нарушений ERC**. Это его
вторая работа: если после правки ядра он перестал проходить проверки, сломано
ядро. Прогонять после каждого изменения в `scripts/`.

Что показано, кроме синтаксиса:

- **Корневой лист без пассивных деталей** — только блоки и внешние разъёмы.
- **Координаты выводов берутся у символа** (`u1.pin("3")`), а не подбираются.
  У резистора под 90° вывод 1 оказывается справа, вывод 2 слева — перепутать
  их значит протянуть провод сквозь корпус.
- **`PWR_FLAG`** объясняет ERC, откуда в цепь приходит питание. Без него
  выводы питания считаются «не запитанными», и отчёт заполняется шумом.
- **Поля закупки заполняются при рисовании**: `MPN`, `Manufacturer`,
  `Supplier`, `Price`, `Alt`, `Note` уходят в BOM. Поле `Alt` не формальность:
  при партии в тридцать штук дефицит одной позиции останавливает всё.
- **Пояснения отвечают «почему», а не «что»**: почему 22 мкФ, а не 1 мкФ, и
  почему TPS7A0533, а не AMS1117.
